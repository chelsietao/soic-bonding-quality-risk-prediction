## 一、專題概述

本專題使用 **100,000 筆模擬鍵合加工紀錄**，建立缺陷風險排序模型，研究固定檢查容量下的缺陷涵蓋率，分析流程包含資料檢查、探索性分析、依時間與批次切分、模型比較、測試評估與模型解釋。

在 15,000 筆測試紀錄中，梯度提升樹選出風險最高的 3,000 筆，涵蓋 2,657 筆缺陷中的 **1,927 筆**，得到 **Precision＝64.2%、Recall＝72.5%**，選中群的缺陷濃度約為隨機選取的 **3.63 倍**。

本專題的核心問題是：**當一組已完成加工的紀錄只能選取 20% 進行優先檢查時，能否利用多個製程量測，把較多缺陷集中到這份清單？** 20% 是本專題設定的評估容量。模型在加工後評分，評估使用後續品質標籤核對選取結果。

分析分成兩個相連的層次。先用參數、機台與時間圖觀察品質差異出現在哪些資料群，再將七個量測合併成每筆紀錄的風險分數。清單中的紀錄仍保留晶圓、批次、機台與時間資訊，便於回到原始資料核對。

本文依 Colab 執行順序收錄 **8 組輸出圖、22 個有效子圖**，每組圖附程式意圖、座標定義及數值解讀，簡報以同一組來源圖分頁呈現，圖表與頁碼對照保存在 `images/colab/index.json`。

### 2.1 每筆資料在流程中的角色

資料中的一列對應一片晶圓的一次模擬加工。加工完成後，溫度摘要、壓力與加工時間已經形成，模型讀取這些摘要與其餘量測，產生缺陷類別分數。後續評估再讀取 `defect_flag`，計算清單實際涵蓋多少缺陷。

以 `temperature_mean` 為例，它描述一筆紀錄的平均溫度；`temperature_std` 描述該筆紀錄內的溫度變動。兩者分別表示中心位置與波動程度，因此同時納入分析。`runs_since_maintenance` 則提供設備自維修後累積加工次數的背景資訊。

### 2.2 數值與分母

全資料缺陷率為 10,046 ÷ 100,000＝10.046%。後續所有圖表都保留自己的資料範圍與分母：機台率使用該機台紀錄數，日期率使用該日紀錄數，模型 Recall 使用該評估集的全部缺陷數。先確認分母，才能比較不同圖表。

## 三、參數區間與觀察缺陷率

![參數分組缺陷率](images/colab/01_parameter_defect_rates.png)

### 程式意圖與紅點定義

`pd.qcut(feature, q=10, duplicates="drop")` 依參數值排序，分成最多十個樣本數接近的區間，再由 `groupby().agg()` 計算各組中位數、樣本數、缺陷數與缺陷率，目的在於觀察不同參數範圍對應的品質結果。

每個紅點代表一組紀錄，**X 軸是組內參數中位數，Y 軸是組內缺陷率**，例如最低溫組有 10,000 筆紀錄，其中 1,530 筆有缺陷，中位數約為 245.07，所以紅點為 **（245.07，15.30%）**，灰色虛線則代表全部資料的 10.05% 缺陷率。

粒子數包含重複的整數值，分位數邊界合併後形成六組，因此紅點數量會依參數分布改變，各組紀錄數可由輸出統計表確認。

### 七個參數的圖形與數值

| 參數 | 觀察圖形 | 具體讀法，數值依圖取近似值 |
|---|---|---|
| 平均溫度 | U 形 | 中間區間約 6%，最低組為 15.30%，最高組約 27% |
| 溫度標準差 | 多數區間隨數值上升 | 較低組約 7.5%，較高組約 13% |
| 平均壓力 | U 形 | 中間區間約 7%，兩端約 17% |
| 加工時間 | U 形 | 中間區間約 7%，較短與較長區間約 16%～17% |
| 對準誤差 | 高值端增幅較大 | 最低組約 2%，最高組約 40% |
| 表面粒子數 | 隨粒子數上升 | 組中位數為 1 時約 6%，為 6 時約 23% |
| 維修後加工次數 | 隨累積次數上升 | 前段約 7%，後段約 14% |

這組圖揭示資料中的單調與 U 形模式，後續模型比較使用相同七個參數，觀察不同方法對這些模式的排序效果。

### 從圖形連到模型選擇

對準誤差的分組曲線在高值端上升較快，平均溫度、平均壓力與加工時間則同時出現低端與高端缺陷率較高的模式。因此，模型需要處理「數值越高風險越高」之外的區間變化。Logistic Regression 提供線性 log-odds 基準，梯度提升樹再透過區間切分學習這些非線性模式。

每個紅點聚合多筆紀錄，連線用來協助閱讀各組的變化。該點的缺陷率同時包含組內其他參數的分布，後續重要性與 PDP 分析則補充模型如何使用這些參數。

## 六、模型方法與設定

### 6.1 Logistic Regression

基準流程使用 `SimpleImputer(strategy="median")`、`StandardScaler()` 與 `LogisticRegression(max_iter=1000)`，中位數、平均值與標準差由訓練集學習，再套用到驗證集與測試集。

模型在 log-odds 尺度上組合七個輸入特徵，提供基準的風險排序，`predict_proba()[:, 1]` 取得每筆紀錄對缺陷類別的分數，供後續門檻判定與排序使用。

### 6.2 梯度提升樹

`HistGradientBoostingClassifier` 以連續的樹模型修正預測，透過數值區間切分表達非線性模式與交互作用，使用的七個參數與訓練資料皆與基準模型相同。

| 參數 | 使用值 | 設定意義 |
|---|---:|---|
| `learning_rate` | 0.05 | 每一步新增模型的影響幅度 |
| `max_iter` | 200 | 提升迭代次數 |
| `max_leaf_nodes` | 15 | 每棵樹葉節點上限 |
| `min_samples_leaf` | 50 | 葉節點最少樣本數 |
| `l2_regularization` | 1.0 | 正則化設定 |
| `early_stopping` | False | 使用設定的提升迭代次數 |
| `random_state` | 42 | 固定隨機性設定 |

## 九、固定 20% 檢查量的模型比較

![模型比較](images/colab/05_model_comparison.png)

程式使用 `np.argsort(-scores, kind="stable")` 將分數由高到低排列，各模型都取驗證集的前 **3,000 筆**，同分依原始列順序處理，這裡的 **20% 是紀錄選取比例**，機率門檻則是另一種警報規則。

本次比較將整個驗證集視為一組評估紀錄，測試集另為一組。每組先取得全部分數，再選最高的 `ceil(紀錄數 × 0.20)` 筆。15,000 × 20%＝3,000，因此兩個模型的清單長度相同，差異反映在清單內涵蓋多少缺陷。

固定門檻 0.20 的意思是分數至少為 0.20 才觸發警報，其警報比例由分數分布決定；選取前 20% 則先固定清單長度，再依排名決定成員。第八節的門檻 0.20 產生 2,231 次警報，可直接看出這兩種設定的差別。

| 模型 | AP | ROC-AUC | 涵蓋缺陷 | 清單外缺陷 | Precision | Recall |
|---|---:|---:|---:|---:|---:|---:|
| Logistic Regression | 0.421 | 0.794 | 958 | 695 | 31.9% | 58.0% |
| 梯度提升樹 | 0.593 | 0.887 | 1,226 | 427 | 40.9% | 74.2% |

右側長條圖直接呈現涵蓋缺陷數，樹模型在相同檢查量下多涵蓋 **268 筆**，清單外缺陷由 695 降到 427，相對下降 **268 ÷ 695＝38.6%**，左側橘色 PR 曲線在大部分區間高於基準，與 AP 提升的結果一致。

## 十一、特徵重要性

![特徵重要性](images/colab/07_permutation_importance.png)

`permutation_importance()` 固定模型，每次打亂驗證集的一個特徵，重複五次，再計算 AP 平均下降量，X 軸為 AP 下降量，Y 軸為特徵名稱，誤差線為五次打亂的標準差。

| 參數 | AP 平均下降量 | 重複標準差 |
|---|---:|---:|
| 對準誤差 | 0.3237 | 0.0065 |
| 平均溫度 | 0.2090 | 0.0092 |
| 加工時間 | 0.1459 | 0.0038 |
| 平均壓力 | 0.0765 | 0.0030 |
| 表面粒子數 | 0.0369 | 0.0027 |
| 溫度標準差 | 0.0046 | 0.0017 |
| 維修後加工次數 | 0.0036 | 0.0012 |

打亂對準誤差後，AP 由約 **0.593 降到 0.269**，顯示它是目前模型依賴程度最高的資訊，平均溫度與加工時間其次，這些數值衡量固定模型在其他特徵仍存在時對各欄位的依賴程度。

## 十三、檢查清單與品質追溯

### 13.1 由模型分數形成清單

1. 加工結束後，收集每筆紀錄的七個數值輸入。
2. 使用已訓練模型的 `predict_proba()` 取得缺陷類別分數。
3. 在同一組紀錄內由高到低排序，同分保留原始列順序。
4. 選取前 `ceil(N × 0.20)` 筆，保留晶圓、批次、機台與時間資訊。
5. 選取完成後，用品質標籤核對清單內外的缺陷組成。

模型分數負責決定優先順序，`defect_flag` 負責事後評估。測試集先完成選取，再計算 1,927 筆涵蓋缺陷與 730 筆清單外缺陷。

### 13.2 測試集 15,000 筆的完整分配

| 群組 | 有缺陷 | 無缺陷 | 合計 | 該群缺陷率 |
|---|---:|---:|---:|---:|
| 前 20% 清單 | 1,927 | 1,073 | 3,000 | 64.23% |
| 其餘 80% | 730 | 11,270 | 12,000 | 6.08% |
| 全測試集 | 2,657 | 12,343 | 15,000 | 17.71% |

這張表同時回答「檢查多少筆」「其中多少筆有缺陷」與「其餘紀錄仍有多少缺陷」。72.5% 的 Recall 以全部 2,657 筆缺陷為分母，64.2% 的 Precision 以清單內 3,000 筆為分母。

### 13.3 可追溯清單的欄位

| 欄位 | 用途 |
|---|---|
| `risk_rank` | 本次評估紀錄內的風險排序 |
| `risk_score` | 模型輸出的缺陷類別分數 |
| `wafer_id` | 回查該筆晶圓紀錄 |
| `lot_id` | 查看是否集中在相同批次 |
| `tool_id` | 對照機台分層結果 |
| `timestamp` | 對照加工時間與缺陷趨勢 |

以下範例由一組已完成加工的 `records` 產生清單。先依 `model_metadata.json` 的特徵順序評分，再將位置索引連回追溯資訊。

```python
import json
import joblib
import numpy as np

with open("models/model_metadata.json", encoding="utf-8") as f:
    metadata = json.load(f)
model = joblib.load("models/bonding_risk_model.joblib")

review = records[["wafer_id", "lot_id", "tool_id", "timestamp"]].copy()
review["risk_score"] = model.predict_proba(records[metadata["features"]])[:, 1]
positions = np.argsort(-review["risk_score"].to_numpy(), kind="stable")
k = int(np.ceil(len(review) * 0.20))
inspection_list = review.iloc[positions[:k]].copy()
inspection_list.insert(0, "risk_rank", np.arange(1, k + 1))
```

## 十四、製程與設備的資料追查

### 14.1 機台差異的追查順序

TOOL_C 的整體觀察缺陷率為 13.46%，比 TOOL_A 高 4.96 個百分點。可先利用既有 `tool_id` 與 `timestamp` 對齊比較時段，再比較各機台的七個參數分布及品質標籤。這樣能把「哪一台較高」轉成「差異集中在哪個期間、哪些參數區間」。

若進一步進行製程調查，可再核對對應的配方、產品與維修紀錄，以相同條件比較設備。這些項目是追查時所需的背景資訊，現有圖表的直接結果仍是機台分層的觀察比例。

### 14.2 時間上升與參數變化

三月後期七天合併缺陷率上升，可依相同日期範圍整理對準誤差、粒子數、溫度及加工時間的分布，查看哪些變化與缺陷增加同時出現。七天合併率計算時先累加缺陷數與紀錄數，再相除，每一天的紀錄量因此直接進入分母。

### 14.3 高風險紀錄與清單外缺陷

重要性分析顯示模型最依賴對準誤差，其次為平均溫度及加工時間。追查清單時，可先對照這些欄位的實際值，再搭配其他參數與批次、機台、時間。PDP 提供整體平均反應，單筆紀錄的分數則來自七個輸入的共同組合。

測試集另有 730 筆缺陷留在清單外。把這群紀錄依機台、時段與參數區間整理，可用相同方式檢視目前排序較難涵蓋的資料群，與已選中的 1,927 筆缺陷對照。

| 分析結果 | 可對應的具體問題 | 核對資料 |
|---|---|---|
| TOOL_C 缺陷率最高 | 相近時段內是否也存在機台差異？ | 機台、時間、參數、標籤 |
| 三月後期缺陷率上升 | 同期哪些參數分布改變？ | 每日樣本數、缺陷數、參數摘要 |
| 對準誤差的重要性最高 | 高分清單的對準誤差分布如何？ | 同一組紀錄的清單內外資料 |
| 溫度與時間呈 U 形 | 清單內是否同時包含低端及高端紀錄？ | 分位數組別、實際值、模型分數 |
| 730 筆缺陷在清單外 | 這群紀錄集中在哪些條件？ | 清單外缺陷的追溯與量測欄位 |

## 十五、各種圖表回答的問題

| 方法 | 計算對象 | 回答的問題 |
|---|---|---|
| 參數分組缺陷率 | 每個數值區間內的實際標籤 | 哪些範圍的觀察缺陷比例較高？ |
| Spearman | 兩欄資料的數值排名 | 兩個欄位是否有一致的單調方向？ |
| 機台及時間率 | 機台或日期內的標籤 | 缺陷較集中在哪些設備與時段？ |
| 固定 20% 模型比較 | 相同清單長度下的標籤 | 哪個模型把較多缺陷排進清單？ |
| Permutation importance | 固定模型打亂欄位後的 AP | 模型排序最依賴哪些輸入資訊？ |
| PDP | 替換一個特徵後的平均模型輸出 | 模型對該特徵範圍呈現什麼反應？ |

例如平均壓力的 Spearman 接近零，但分組圖仍呈 U 形，而打亂壓力後 AP 平均下降 0.0765。三個數值分別描述單調方向、觀察形狀與模型依賴度，放在一起能更完整地閱讀結果。
